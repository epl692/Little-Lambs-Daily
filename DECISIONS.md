# Decisions and framework gaps

Running log. Where SPEC.md and the framework disagree, the framework wins and the conflict is recorded here.

## D-001 Framework consumption
Git submodule at `framework/`, pinned to `356cfc8` (master, includes 004 blob sync). The repo root is an npm workspace
over `framework/packages/*`, so `@sync/*` resolve to the framework's TypeScript source (as in its own sample app).
`tsconfig.json` repeats the framework's `paths` with a `framework/` prefix.

## D-002 Svelte and app-build (SPEC 10.2, option 1)
`ui/` is built with Vite in library mode to `ui/dist/ui.js` (exports `mount(target, api)`); the `daycare` module's root
view imports that file. Component CSS is `css: 'injected'` so the one file is self-contained. `npm run build` runs
`build:ui` first. No upstream change to app-build needed.

## D-003 Inline theme script is not allowed (SPEC 6.2)
The generated CSP is `script-src 'self' blob:`, so an inline pre-paint script would be blocked. The same logic ships as
`public/theme-init.js` (listed in `assets`, loaded synchronously at the top of `<body>`). `ui/src/lib/theme.ts` mirrors it.

## D-004 Banned imports in app code (SPEC 8, 10.1)
`app-build` bans value imports of `@sync/core` and `@sync/spaces` from app files, including `app.config.ts`, which the spec
said may use them. Consequences:
- `assertSecureCore(core)` can't be called from app code; the secure-core test will live in `tests/` instead.
- The authz validator (`modules/daycare/authz.ts`) will import only types, and is registered through the `core` object
  handed to the `blobs({ core, spaces })` hook / `onReady` (`core.registerValidator` exists). No framework change needed.
Revisit in phase 2 if role lookup from inside a validator proves impossible (SPEC 3.3).

## D-005 Local tooling
- `fast-check` is a root devDependency because `@sync/testkit` needs it and the framework's own devDeps aren't installed.
- Docker Desktop is installed per-user, so `docker` may be missing from PATH in an already-open shell
  (`%LOCALAPPDATA%\Programs\DockerDesktop\resources\bin`). The relay image builds and the pairing e2e passes against the container
  (`docker compose -f relay/docker-compose.yml up -d --build`). Without Docker, `npm run relay` runs the same relay
  (ws://localhost:8787, set `BLOB_DIR=./blobs` for attachments).
- The relay Dockerfile builds from `framework/` with its own lockfile.

## D-006 Placeholder art
Icons are generated by `npm run icons` (original cream cloud on teal). Replace with real artwork later.

## D-007 Authz validator (SPEC 3.3): feasible, no framework change needed
`modules/daycare/authz.ts` implements `daycare-authz`. It resolves device -> user -> role with `spaces.members(space)`
(cached per Space, cleared on `member:changed`), defers when the device is unknown, and uses `ctx.existing` for ownership.
It is structural (imports nothing from @sync/*) and registered in `app.config.ts` inside the `blobs({ core, spaces })`
hook, which runs before transports start, so it is in place before any remote packet arrives.
Beyond the spec, as hardening (enforced for providers too):
- **Provenance on create:** `createdBy` must equal the author's user and `createdByRole` the role implied by their
  membership (Owner = provider, Editor = parent). Without this a parent could post as a provider.
- **Frozen fields on parent updates:** `kind`, `child`, `createdBy`, `createdByRole` (so a parent's note can't become a nap).
- Default deny for any type or operation not listed. Viewers are rejected for all daycare writes.
Tested with fakes (tests/unit/authz.test.ts) and on real encrypted nodes (tests/contract/authz.integration.test.ts), where a
modified parent client without the validator is rejected by the provider and an observer. Mutation-checked: removing the peer
validators makes the forgery tests fail.

## D-008 Schemas (SPEC 5)
All seven types are in `modules/daycare/schema/`. `objectCheck` on `entry` requires the kind-specific fields. Choices:
- Staff `settings` gained `sinceThresholdMinutes` (default 180) for the configurable amber chip (SPEC 6.3).
- Bottle `ozFinished` may not exceed `ozOffered`; oz values are multiples of 0.5.
- `objectCheck` is create-only (framework rule), so later updates are not re-checked against kind rules.
- Deterministic reaction IDs are deferred to phase 6 with the UI that creates them.
- The photo kind's positive case needs a real blob reference, so it is exercised with the attachments work in phase 7.
- Blobs are switched on now (500 MB budget) because the schemas have blob fields; the hook is shared with the validator.

## D-009 Framework gap: join and link approval (SPEC 4.3, 4.5) — upstream PR
`startApp` opened the secure core without `approveJoin`/`approveLink`, whose default is to refuse, so invites with
`approval: 'required'` and device links could never complete in an app-build app. Fix: two optional `AppConfig` fields
passed through to `openSecureCore` (about 10 lines + a test). Raised as
[epl692/Sync-PWA-Framework#4](https://github.com/epl692/Sync-PWA-Framework/pull/4); `framework/` is pinned to that
branch's commit (`4200397`) until it merges. **After it merges, move the submodule pin to master.**
The app answers through `modules/daycare/bridge.ts`: the UI registers an approver (the SAS dialog); with none mounted the
answer is "no".

## D-010 How the UI reaches Spaces
The module declares `access: { spaces: { read: 'any', write: 'any', manage: true } }`, which puts the full Spaces API on
`ctx.spaces.admin`. The UI sees it through structural types (`ui/src/lib/types.ts`), never framework imports. QR drawing
(`qrToSvg`, from identity-invite) reaches the UI via the bridge, shown as an `<img>` data URL, not `{@html}`.
All onboarding logic is `ui/src/lib/service.ts`, tested on real encrypted nodes.

## D-011 Onboarding design choices
- **Which Space is which:** by name suffix (" Staff", " Family"). A device is a provider when it owns a Staff Space, a
  parent when it only holds family Spaces. Only affects that device's own UI; authority comes from the Space itself.
- **Membership lags the join:** `spaces.list()` omits a Space until the device has synced its own join event, so the join
  screen waits (up to 30s) for it before showing a home screen.
- **Second provider:** joins the Staff Space as Owner (always needs approval). Access to families is by single-use
  `approval: 'auto'` Owner invites left in the Staff Space as `daycare.staffInvite` (deterministic id per provider+family, so
  two devices converge) and accepted automatically. The inviting device must be online; the receiver retries every 30s and a
  fresh invite is issued once one expires. `staffInvite` gained `expiresAt` for this.
- **Relationship:** stored in the display name, "Erin (Mom)", so providers see it in member lists.
- **Invite links:** `<page URL>#/join/<payload>`. On open the hash is removed from the address bar and kept in memory.
- **Tracking my invites:** the framework can't list invites, so each device remembers the ones it made (localStorage) to
  show and cancel them.
- **Relay URL** is a build constant (`RELAY_URL` in `constants.ts`) because the CSP `connect-src` must list it.
  A runtime override in Settings is deferred; it could only work for origins the build already allows.

## Deferred from phase 3
- WebRTC peer-to-peer fallback (its pairing is a manual code exchange; needs its own UI) and in-app QR scanning
  (phone cameras open the link directly; pasting works today).
- Removing a provider (Staff Space) and per-device revocation UI; the service has `removeMember`/`revokeDevice`.
- Install hint is basic (Chrome prompt, iOS instructions).

## D-012 Roster and timeline (phase 4)
- **Pure logic is separate and unit-tested:** `ui/src/lib/{time,format,timeline}.ts` (day ranges built from calendar fields so DST days
  are right, US 12-hour formats, card text, filters, ordering, per-child status, since-chips).
- **Status:** a nap with no end means napping; otherwise the later of check-in/check-out decides; provider care logged with no
  check-in still means "here". A parent's home note does not.
- **Since-chips** (🍼 feeding, 🧷 diaper) show only for children who are here, ignore entries in the future, and turn amber at
  `sinceThresholdMinutes` (Staff settings, default 180). The Settings screen does not expose it yet.
- **Timeline visual** (line, dots, boxes) is plain CSS and is verified by geometry in `tests/e2e/timeline.spec.ts` at 375px in
  both themes (line 2px and full-height, dot 12px and centred on the line and on the header row, boxes to the right, no sideways
  scroll). Screenshots are written to `test-results/shots/` for eyeballing. Pixel-diff baselines are not used.
- **Roster** is the child grid (Here now / All children; defaults to Here now when anyone is here). The old family list moved to a
  **Families** screen (👪). Parents see their child's timeline directly, with a sibling switcher and an "All" view.
- **Day navigation:** arrows, swipe (horizontal, vertical scroll untouched), tapping the date opens the native date picker, and a
  Today button. Order (newest/oldest first) is device-local and remembered.
- **Not in this phase** (by the build plan): add flow, nap timers and the "Asleep now" banner (5), reactions and threads (6),
  photos in cards (7: cards show a photo count), daily summary and exports (9), the sync status pill (10).
- **Test data** is seeded through the dev build's `window.__syncHost` (`npm run e2e` builds the dev build first). Tests that rely
  on seeded entries being in the past skip before 6 AM local time.

## D-013 Add flow (phase 5)
- **Engine vs UI:** `ui/src/lib/log.ts` builds entries (one per child, shared `batchId` for 2+, all-or-nothing), remembers last-used
  values and recent suggestions (device-local), wakes naps, edits, undoes. Tested on real encrypted nodes
  (`tests/contract/logging.integration.test.ts`). The sheet (`AddSheet.svelte`) is state and layout only.
- **Undo** is the framework's: undoing a create deletes it, undoing a wake restores the open nap, undoing a delete restores the
  entry. It reverses *this device's* most recent change to that object, inside the retention window. The toast lasts 6s.
- **`daycare.entry` now has `merge.editResurrects`** — the framework refuses to undo a delete otherwise. Consequence: an edit that
  races a delete on another device brings the entry back. Judged acceptable for a daily log.
- **Authz bug found and fixed:** undoing a delete writes an update that re-asserts *every* field, which the parent frozen-field
  rule (`kind`, `child`, `createdBy`, `createdByRole`) rejected. Frozen fields may now be re-written with the same value, never
  changed. Covered by unit and real-node tests, and mutation-checked.
- **Svelte state proxies cannot go into IndexedDB** ("could not be cloned"). `clean()` copies arrays/objects to plain values.
- **Who step:** skipped when the sheet is opened for a child (long-press or "+" on a card, the "+" on a child's timeline, a parent's
  single child). "All checked in" selects the children who are here. Check-in lists those not here first, other kinds those here.
- **Quick add:** long-press a roster card (500 ms) *or* the "+" in its corner (keyboard and mouse users cannot long-press).
- **Diaper** saves on the type button; the extras chips (More…) apply to that save.
- **Bottle:** "finished" follows "offered" until set by hand and can never exceed it (the schema forbids it too).
- **Nap banner** shows open naps from any day (a nap left open overnight still shows, with the 3-hour "still sleeping?" hint).
- **Card menu (⋯)** sits in the card footer so it can never change the header row the timeline dot is centred on. Providers can
  change anything; parents only their own. Edit changes one entry and marks it "edited".
- **Deferred:** Photo tile (phase 7), "Edit for all in batch", limiting a parent's edit of their own check-in time to the same day
  (open item 3 is "yes" for now with no day limit), focus trapping in the sheet beyond moving focus into it.

## D-014 Reactions and threads (phase 6)
- **Engine vs UI:** `ui/src/lib/threads.ts` (toggle, reply, edit, delete, grouping) is tested on three real encrypted nodes
  (`tests/contract/threads.integration.test.ts`); `ReactionBar`, `Thread` and `WhoReacted` are layout only.
- **Reaction ids** are the deterministic string `reaction:<entry>:<user>:<emoji>` (not a hash: it is already unique and readable).
- **`daycare.reaction` and `daycare.comment` now have `merge.editResurrects`.** A create on a deleted id does not bring it back
  (found by the test), so tapping the same emoji again after removing it only works if the type resurrects; comments need it for
  "Delete, then Undo". Same consequence as D-013 for entries.
- **`daycare.comment` gained a required `at` timestamp** (SPEC 5.3 lists none). Replies need a time to show and to sort by.
- **Who reacted:** long-press or right-click a pill, or the ⓘ button (keyboard users cannot long-press). Lists every emoji with
  names, "You" first. Names come from the Space's member list ("Erin (Mom)").
- **Permissions** (already in the authz validator, now exercised): anyone may react and reply; a parent edits or deletes only their
  own reply or reaction; a provider can delete (not edit) anyone's reply. Posting a reply as someone else's role is rejected.
- **Reply undo:** sending shows an Undo toast (removes the reply); deleting shows one that restores it.
- **Deferred:** a "Reply" count on collapsed cards is shown, but notifications of new replies are not (no push in this app).

## D-015 Photos (phase 7)
- **Pipeline** (`ui/src/lib/photos.ts`): the picker opens first (Photo tile → system camera/gallery, multi-select, up to 12), each
  image is re-drawn on a canvas at ≤2048px long edge, JPEG q0.82, with EXIF orientation applied to the pixels first. Redrawing
  drops all metadata (EXIF, GPS, camera make); an e2e test plants a fake GPS/Make segment and checks it is gone from the stored blob.
- **Thumbnails:** SPEC says "thumbnails first, full image on tap" but the schema had one blob per photo, so `daycare.entry` gained
  an optional `thumbs` list (480px, q0.7, same order as `photos`). The grid loads only thumbnails; the viewer loads the full image.
- **One entry per child, one copy per Space:** each entry gets its own attachments made in that child's Space with the entry's id
  (allocated first and passed to `create({ id })`). Siblings in one family still get their own entry and attachment (deduped by the
  framework). All or nothing; Undo removes every entry. A warning chip shows "Visible to N families" when the children span
  more than one Space.
- **Rendering:** the UI fetches with `blobs.toBlob(ref)` into an object URL (the CSP allows `blob:` images) rather than `<sync-blob>`:
  that element waits for a tap on "Download", which is wrong for a photo grid. Failed loads show "Tap to retry".
- **Viewer:** full screen, arrows, swipe, Escape, Save (download link). Photos are providers-only (parents have no Photo tile and
  the validator already refuses them).
- **Relay needs `BLOB_DIR`:** photos did not reach the second device through a relay without blob storage. The Docker compose file
  sets it; the e2e relay now does too (`playwright.config.ts`). Treat it as required for photos.
- **Deferred:** caption-only edits (photos can't be added or removed after posting), pinning today's photos on provider devices,
  eviction tuning, ZIP export of photos (phase 9), per-photo delete, a "photos downloading" indicator beyond the placeholder.

## D-016 Parent experience (phase 8)
- **Already in from earlier phases:** parent home, sibling switcher with an All view, status header, check-in/out and From Home for
  parents, and the permission-filtered UI (no provider tiles, no menu on the provider's entries). Phase 8 added what was missing.
- **Child profile** (`ChildProfile`): reached from the child row on the parent home and a Profile button on a provider's child timeline.
  Allergies and care notes are read-only; Family notes is a textarea that parents and providers both write (the validator already
  lets a parent change `familyNotes` and nothing else on a child). Lists the family's parents.
- **Same-day time edits (SPEC 13.3):** when a parent edits their own entry, the time picker is limited to that entry's day and
  save refuses another day. This is a UI rule only: the validator does not check it, because a day depends on the device's time zone
  and every peer must reach the same verdict. A modified client could move its own entry's time; it still cannot touch anyone else's.
- **Leave family:** Settings shows a Leave button per family for parents (`admin.leave`), then returns to the welcome screen.
- **Deferred:** changing your own display name (the framework has no rename call), removing a parent or revoking a device from a
  provider screen, notifications for new items.

## D-017 Reports and exports (phase 9)
- **All on-device**, from local data, so it works offline. Pure logic in `ui/src/lib/reports.ts` (unit-tested); screens are `DaySummary`
  (a card on the timeline) and `Reports` (Settings → Reports and exports).
- **Daily summary:** arrival/departure and by whom, nap total with each nap (an open nap counts up to now), bottles and oz finished,
  food, wet/soiled diapers ("both" counts as each), photo count, notes. One card per child. Pinned at the top of past days that
  have entries, a button for today. **Deviation:** Share sends *text* (Web Share API, else a `.txt` download); the spec says
  image/PDF. A PDF comes from "Print / PDF" (the browser's print dialog with only the card visible). An image is not built.
- **Attendance** (provider): date range + Everyone / whole family / one child. One row per child per day: the first check-in and the last
  check-out after it (a double-tapped check-in does not create a second row). A day with a check-in and no check-out, or the reverse, is
  flagged (text under the child's name, not just colour). CSV has the spec columns plus a trailing `flag`; it starts with a BOM so Excel reads
  accents, and any text cell starting with `= + - @` gets a leading `'` so a typed name can never run as a spreadsheet formula.
  Printing gives one page per week (Monday start) with a signature line.
- **Backup ZIP** (everyone; a parent only ever has their family's data): `data.json` (`schemaVersion: 1`, spaces, every child, entry, reply
  and reaction) and, if ticked, `photos/<child>/<date>_<time>_<n>_<name>` (full-size, fetched first if not on the device, with progress).
  A photo that cannot be fetched is listed under `missingPhotos` instead of failing the export. Staff invites (which hold join
  links) and settings are never exported. Folder names are sanitised (a child named `..` cannot escape its folder).
- **After Leave family** the app only shows families the device still belongs to (the framework keeps what was synced and has no purge call).
- **Deferred:** daily summary as an image; attendance by a day's hours worked in a facility timezone
  (all times are the device's local time).

## D-018 Polish and hardening (phase 10), restore, lazy ZIP
- **ZIP tool loads on first use.** The framework's bundler folds ordinary dynamic imports into the one app file, so `import()` would
  not have deferred anything. Instead `scripts/build-zip.mjs` bundles fflate into `public/zip.js` (generated, git-ignored, built by
  `npm run build`), which ships as a precached asset and is loaded by URL the first time someone exports or restores (`ui/src/lib/zip.ts`).
  The app script is ~16 KB smaller (gzip); the tool still works offline.
- **Restore (SPEC 12 said out of scope; now in):** provider only, from the Backup ZIP. Families match by id, then by name, else are created
  (parents must be invited again). Everything keeps its original id, so a second restore adds nothing. Because the validator forces
  `createdBy` to be the writer, entries and replies come back **under the person restoring** with the original author's name kept; a
  parent's entry loses its "from home" mark and cannot be edited by that parent. **Reactions are not restored.** Photos are re-uploaded from
  `photos/` with new thumbnails; a photo entry whose files are missing is skipped and reported. A restore previews what it will add first.
  Not restored: the staff list, settings, invites, avatars. An item deleted on this device stays deleted.
- **Sync pill** (● Synced / ◐ Connecting / ○ Offline; tap for details): the transport module publishes its state through the bridge
  (`bridge.sync`); the pill also watches the browser's online/offline events. SPEC's "Syncing (n)" count is **not available**: the framework
  exposes no pending-packet count to apps, so "Synced" means "connected to the relay".
- **Update banner:** the UI watches the service worker itself (`ui/src/lib/updates.ts`); "A new version is ready → Reload". It never
  reloads on its own, so nobody loses a half-written entry.
- **Accessibility:** an automated axe WCAG A/AA scan of every main screen in light and dark (a real a11y test, in CI with the rest), focus
  trapped in sheets and dialogs with Escape and focus-return (`ui/src/lib/focus.ts`), reduced motion verified. Found and fixed: a date button
  whose spoken name did not contain its visible text, an unlabeled hidden file input, a sideways-scrolling table unreachable by keyboard.
  A person with a screen reader still needs to do a pass (DEPLOY.md section 9).
- **Performance:** 150-entry day: the first screenful in ~17 ms and all cards in ~115 ms on a desktop; add sheet opens in ~15-35 ms. The
  timeline paints 24 cards at once and fills in the rest over the next frames. The test guards regressions on a fast machine; the spec's
  budget is for a mid-range Android phone, which has **not** been measured. (`content-visibility` was tried and made it slower.)
- **Offline cold start:** tested end to end (ten entries logged offline, reload with no network, everything still there, all sync on reconnect).
- **Settings:** "since" threshold control and the real version number added. **Not possible as specced:** a relay URL override. The page's
  security policy only permits the relay address baked in at build time, and widening it to any address would weaken it. Changing
  relay means rebuilding (DEPLOY.md). **Deferred:** editing the daycare/app name (it is stored in the provider-only Staff Space, so parents'
  devices would keep the built-in name), changing your own display name (no framework rename call), removing a parent or revoking a device
  from a provider screen.
- **Bundle:** the whole app script, framework included, is 150 KB gzip (budget: under 200 KB excluding the framework); the ZIP tool is a further 6 KB, loaded only when used.
