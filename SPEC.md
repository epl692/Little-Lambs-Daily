# Little Lambs Daily — Product & Build Spec

> **For Claude Code.** This is the full spec for an offline-first, mobile-first childcare logging PWA built on
> [epl692/Sync-PWA-Framework](https://github.com/epl692/Sync-PWA-Framework). Read this whole file, then read the
> framework's `README.md`, `docs/app-config.md`, `docs/building-a-module.md`, `docs/blobs.md`, and
> `specs/002-spaces-security-identity/contracts/authority-rules.md` before writing code. Where this spec and the
> framework disagree, **the framework's contracts win**: note the conflict in `DECISIONS.md` and pick the closest
> behavior to this spec's intent.

---

## 1. Summary

A daily-log app for a licensed family home daycare. **Providers** log what each child did (check-in/out, naps,
bottles, snacks, meals, diapers, photos, notes). **Parents** see their own child's day as a live timeline, react with
emoji, reply in threads, log what happened at home, and can check their child in or out.

- No accounts, emails, or passwords. Devices join by **one-time QR code or link** generated by the framework's
  invite system (`spaces.invite` → `url` + `qrPayload`).
- Works fully offline; syncs through a self-hosted relay when online, or directly device-to-device (WebRTC).
- All data is end-to-end encrypted by the framework; the relay only ever sees ciphertext.
- **Every common action takes 3 taps or fewer.**

**App name:** a single config constant, `APP_NAME`, default `"Little Lambs Daily"`. Daycare display name
`DAYCARE_NAME`, default `"Bri's Little Lambs"`. Both editable in Provider Settings, stored in the Staff Space.

## 3. Roles and permissions

The framework has three Space roles: **Owner, Editor, Viewer**. Editors can create/update/delete *any* ordinary
object, so app-level roles are layered on top with a **custom `PacketValidator`** (see §3.3).

### 3.1 Role mapping

| App role | Framework role | In which Spaces |
|---|---|---|
| **Provider** | **Owner** | The Staff Space and **every** family Space. Each provider (e.g., Briana and Eric) is a separate framework user, so entries show who logged them. |
| **Parent / family member** | **Editor** (restricted by the app validator) | Only their own family's Space. |

A provider's extra phones/tablets join with `spaces.linkDevice()` / `joinAsDevice()` (same user, new device), confirmed
with the framework's 5-word SAS code.

### 3.2 Permission matrix

| Action | Provider | Parent |
|---|---|---|
| View own family timeline | ✔ (all families) | ✔ (own family only) |
| Create/edit children | ✔ | ✘ (can view profile; may edit a "Notes from family" field only, see §5) |
| Check-in / Check-out | ✔ | ✔ own children |
| Nap, Bottle, Snack, Meal, Diaper, Photo, Provider Note | ✔ | ✘ |
| Home event (from home) | ✘ (n/a) | ✔ |
| Family Note | ✘ | ✔ |
| Thread reply on any timeline item | ✔ | ✔ |
| Emoji reaction on any timeline item | ✔ | ✔ |
| Edit/delete an item | Own items always; **any** item (moderation) | Own items only |
| Invite parents, revoke devices, remove members | ✔ | ✘ |
| Exports | ✔ all | ✔ own family (daily summary + their data export) |

### 3.3 Enforcing it (`daycare-authz` validator)

Register a `PacketValidator` (phases `send` and `apply`) from app code; the app has the open core in the
`blobs({ core, spaces })` hook and in `onReady`. Rules:

1. Author's role in the packet's Space is **Owner** → accept (the framework already checked the signature and membership).
2. Author's role is **Editor** (parent):
   - `create` allowed only for types/kinds: `entry` with `kind ∈ {checkin, checkout, home, familyNote}`, `comment`, `reaction`.
   - `update`/`delete` allowed only when the existing object's `createdBy` user equals the author's user
     (`ctx.existing` is available in the `apply` phase).
   - `daycare.child`: update only the `familyNotes` field; no create/delete.
   - Anything else → `reject` with reason `"daycare-role"`.
3. Resolve device → user → role with `spaces.members(space)` (cache it; refresh on the `member:changed` security event).
   If the author's device isn't known yet, return `defer` (the framework retries on `revalidate()`).

Schema checks aren't authorization (the framework says so); this validator is the authorization layer. Write
contract tests that show a parent device can't create a `nap` entry or delete a provider's entry, and that every peer
rejects the packet consistently.

> **If the framework can't support this cleanly** (for example, no role lookup from inside a validator), say so in
> `DECISIONS.md` and propose the smallest framework change (an upstream PR to the same author is fine).
> Don't silently fall back to UI-only enforcement.

## 4. Spaces, pairing and onboarding

### 4.1 Spaces

- **Staff Space** (`"<DAYCARE_NAME> Staff"`): provider-only. Holds `daycare.settings`, `daycare.familyIndex` (one
  object per family Space: `{ spaceId, familyName }`), and `daycare.staffInvite` handoff objects (§4.4).
- **Family Space** (`"<Family name> Family"`): holds the family's `daycare.child` objects and every timeline object
  for those children.

### 4.2 First launch (provider)

1. Welcome screen with two big buttons: **"I'm the provider (set up daycare)"** and **"I have an invite"** (paste/scan).
2. Provider setup: enter your display name (e.g., "Miss Bri") and the daycare name → `spaces.signUp(name)` →
   create the Staff Space → land on the empty Roster with a "Add your first family" call to action.

### 4.3 Adding a family and pairing a parent (target: under 60 seconds)

1. Provider: **Roster → "+ Family"** → family name + first child's first name (more children later) → creates the
   family Space, a `familyIndex` entry, and the `child` object(s).
2. Tap **"Invite a parent"** on the family → `spaces.invite(spaceId, { role: 'editor', maxUses: 1, expiresAt: now + 24h })`.
   Show a full-screen **QR code** (`qrToSvg(qrPayload)`) with **Copy link** and **Share** (Web Share API) buttons, plus
   expiry text. Any number of invites per family (Mom, Dad, Grandma); each is single-use.
3. Parent scans the QR with their phone camera → opens the PWA URL (the secret lives in the `#fragment`) → enters a
   display name and their relationship ("Mom", "Dad", "Grandpa", free text) → `spaces.accept(...)`.
4. **Join approval:** use invite `approval: 'required'`. Both screens show the framework's **5-word SAS**; the
   provider taps **"Words match, approve"**. Settings toggle: "Require approval for parent invites" (default **on**).
5. Parent lands on their child's timeline, with a one-time hint card: "Add to Home Screen for the best experience"
   (platform-specific instructions; use `beforeinstallprompt` where available).

The provider can see and **revoke** unused invites and remove family members/devices
(`revokeInvite`, `remove`, `revokeDevice`; key rotation is automatic).

### 4.4 Adding a second provider

1. Provider A: **Settings → Staff → "Invite a provider"** → Staff Space invite with role `owner` if the framework allows
   inviting Owners; otherwise `editor` followed by `setRole(…, 'owner')` once joined.
2. Once provider B joins the Staff Space, provider A's device automatically adds B to **every** family Space as an
   Owner: either a direct member add if the framework supports it, or by generating a single-use invite per family
   Space, storing it as a `daycare.staffInvite` object in the Staff Space (encrypted) that B's device accepts
   automatically and then marks consumed.
3. New family Spaces created later automatically include all current staff (same mechanism).

### 4.5 Linking more devices for the same person

Settings → **"Link another device"** → `spaces.linkDevice()` shows a code/QR → new device `joinAsDevice(code)` →
both show SAS → approve. Works for providers and parents.

## 5. Data model (`daycare` module)

All types are in one module with id `daycare` (types register as `daycare.<name>`). Every timeline object carries
`createdBy` (user ID), `createdByName` (display-name snapshot), and `createdByRole` (`provider | parent`) so the UI
renders without member lookups. Timestamps are ms epoch (`timestamp` fields).

### 5.1 `daycare.child`
| Field | Type | Notes |
|---|---|---|
| `firstName` | string, required, ≤40 | |
| `lastName` | string, ≤40 | |
| `nickname` | string, ≤40 | Displayed if set |
| `birthDate` | string `YYYY-MM-DD` | Shows age ("7 mo", "2 y 3 mo") |
| `avatar` | blob, `image/*`, ≤5 MB | Provider-set |
| `color` | enum of 8 palette keys | Avatar fallback color |
| `allergies` | string, ≤500 | Shows a red ⚠ badge on the child chip **and** on every food/bottle entry sheet for that child |
| `careNotes` | string, ≤1000 | Provider-visible notes (e.g., "pacifier at nap") |
| `familyNotes` | string, ≤1000 | Editable by parents |
| `active` | boolean, default true | Unenrolled = archived, never hard-deleted (keeps records) |

### 5.2 `daycare.entry` (every timeline item)
One type with a `kind` discriminator so the timeline is a single live query. Use the schema's `objectCheck` to
require kind-specific fields.

| Field | Type | Used by |
|---|---|---|
| `child` | ref → child, required | all |
| `kind` | enum: `checkin, checkout, nap, bottle, snack, meal, diaper, photo, providerNote, familyNote, home` | all |
| `at` | timestamp, required | Event time (nap start for naps) |
| `endAt` | timestamp | Nap end; null while sleeping |
| `batchId` | string | Same value on every entry created in one multi-child save (lets the UI offer "edit for all") |
| `mealPeriod` | enum: `breakfast, amSnack, lunch, pmSnack, dinner, other` | snack, meal |
| `served` | string ≤200 | snack, meal ("Mac & cheese, peas, pears") |
| `amount` | enum: `all, most, some, none` | snack, meal |
| `bottleContents` | enum: `breastMilk, formula, milk, water, other` | bottle |
| `ozOffered` | number 0–16, step 0.5 | bottle |
| `ozFinished` | number 0–16 | bottle |
| `diaper` | enum: `wet, soiled, both, dry` | diaper |
| `diaperNote` | enum list: `rash, creamApplied, potty` | diaper (optional chips) |
| `photos` | list of blob, `image/*`, ≤12 items, ≤20 MB each | photo (caption goes in `text`) |
| `text` | string ≤2000 | notes, photo caption, home event details, optional on every kind |
| `homeKind` | enum: `slept, ate, bottle, diaper, medicine, mood, other` | home |
| `mood` | enum: `great, ok, fussy, sick` | home (optional) |
| `by` | string ≤40 | checkin/checkout: "Dropped off by" / "Picked up by" (defaults to the device user's relationship) |
| `createdBy`, `createdByName`, `createdByRole` | string | all |
| `editedAt` | timestamp | Set on edits; UI shows "edited" |

### 5.3 `daycare.comment` (thread replies)
`target` (ref → entry, required), `text` (≤2000, required), `createdBy`, `createdByName`, `createdByRole`, `editedAt`.
Separate objects (not a list on the entry) so concurrent replies never collide under field-level LWW.

### 5.4 `daycare.reaction`
`target` (ref → entry, required), `emoji` (enum, required), `createdBy`. **One object per (target, user, emoji)**:
toggling off deletes it. Use a deterministic object ID `hash(target + user + emoji)` (via `create(..., { id })`) so a
double tap on two offline devices converges on one reaction.

Emoji set (enum, in display order): 👍 ❤️ 😂 😮 😢 😠 💩 🎉. Store them as keys (`thumbsUp, love, laugh, wow, sad,
mad, poop, party`) and render the emoji.

### 5.5 Staff Space types
- `daycare.settings`: `daycareName`, `appName`, `requireApproval` (bool), `defaultInviteHours` (int, 24).
- `daycare.familyIndex`: `spaceId`, `familyName`, `archived`.
- `daycare.staffInvite`: `forUser`, `spaceId`, `artifact` (string), `consumed` (bool).

Device-local (localStorage, not synced): theme choice, last selected child, dismissed hint cards.

## 6. Screens and UX

### 6.1 Design language
- **Mobile-first**, designed at 375×812 and scaling up to a centered max-width of 640px with a roomier layout on tablets.
- Sleek and modern: soft rounded cards (16px radius), generous spacing, one accent color (default a warm teal
  `#14B8A6`; theme color in the manifest), subtle shadows in light mode and slightly lighter surface elevation in dark mode.
- System font stack (`-apple-system, Segoe UI, Roboto, Inter, sans-serif`); 16px base; tabular numerals for times.
- Each `kind` has an **emoji icon + color token** used everywhere (chips, timeline dots, filters):

| Kind | Icon | Color token |
|---|---|---|
| Check-in / out | 🏠➡️ / 👋 | green / slate |
| Nap | 😴 | indigo |
| Bottle | 🍼 | sky |
| Snack | 🍎 | orange |
| Meal | 🍽️ | amber |
| Diaper | 🧷 (wet 💧 / soiled 💩 / both) | teal / brown |
| Photo | 📸 | pink |
| Provider Note | 📝 | violet |
| Family Note | 💬 | rose |
| From Home | 🏡 | lime |

- Tap targets ≥ 48px. Bottom-anchored primary actions (thumb zone). Haptic feedback (`navigator.vibrate(10)`) on save
  where supported.
- **Accessibility:** WCAG AA contrast in both themes, full keyboard and screen-reader support, `prefers-reduced-motion`
  respected, emoji always paired with a text label for screen readers.

### 6.2 Theme
CSS custom properties on `:root[data-theme=light|dark]`. Setting: **System (default) / Light / Dark**. "System" follows
`prefers-color-scheme` live. Update `<meta name="theme-color">` to match. No flash of the wrong theme: apply the stored
choice in an inline script before first paint.

### 6.3 Provider home: **Roster**
- Header: daycare name, date, sync status pill (see §6.8), settings gear.
- **"Asleep now" banner** (sticky, only while any nap is open): avatars plus live elapsed timers; tap an avatar to wake
  that child; a **"Wake all"** button.
- Grid of **child cards** (2 columns on phone): avatar, name, status (`Checked in 8:02a` / `Napping 0:42` /
  `Not here` / `Picked up 4:15p`), and "since" chips for the last bottle/feeding and last diaper ("🍼 2h 10m",
  "🧷 1h 05m"; the chip turns amber after a configurable threshold, default 3h, a gentle nudge rather than an alert).
  Allergy ⚠ badge.
- Tap a card → that child's **Timeline**. Long-press a card → quick-add sheet pre-filtered to that child.
- Section toggle: **Here now / All children**.

### 6.4 Parent home
- Their child's **Timeline** directly. If the family has siblings, a segmented avatar switcher at the top (plus an
  "All" option that merges siblings with name labels).
- Status header card: "Checked in at 7:58a by Mom · Napping now 😴 0:35".

### 6.5 Add flow: **3 taps maximum**

A floating **"+" button** (bottom-right, 64px) opens a bottom sheet. Defaults do the heavy lifting: time = now, child =
the current timeline's child (or the children checked in), last-used values remembered per kind.

**Step 1: What?** A grid of large kind tiles, filtered by role.
- Provider: Check-in, Check-out, Nap, Bottle, Snack, Meal, Diaper, Photo, Note.
- Parent: Check-in, Check-out, From Home, Note.

**Step 2: Who?** Child avatars as toggle chips. Skipped automatically when opened from a single child's timeline (with
an "Add more kids" link available in step 3). Provider shortcut chip: **"All checked in"**. For Check-in, only children
not yet checked in show first; for Check-out, only children checked in.

**Step 3: Details + Save.** One compact screen, every field pre-filled, big **Save** button pinned to the bottom. A
"time" pill ("Now ▾") opens a time picker if it needs to be backdated.

| Kind | Step 3 contents | Fastest path |
|---|---|---|
| Check-in | "Dropped off by" chips (recent names + device user), optional note ("last bottle 6:45") | + → Check-in → Save (2–3 taps) |
| Check-out | "Picked up by" chips, optional note | same |
| Nap | **Start nap** (default) or "Log past nap" (start/end pickers). Opens timer | + → Nap → Start (3) |
| Bottle | Contents chips (last used preselected), oz offered stepper (last used), oz finished stepper (defaults to offered) | + → Bottle → Save (3) |
| Snack / Meal | Meal period (auto-guessed from time of day), "Served" text with recent suggestions as chips, **per-child amount chips** (All/Most/Some/None, default All) when several kids are selected | + → Meal → Save |
| Diaper | **Wet / Soiled / Both / Dry** as big buttons. **Tapping one saves immediately**; optional rash/cream chips via "More…" | + → Diaper → Wet (3) |
| Photo | Opens camera / gallery picker (multi-select) first, then child tag chips + caption | + → Photo → pick → Save |
| Note | Text box (autofocus), kind = Provider Note or Family Note by role | + → Note → type → Save |
| From Home (parent) | Chips: Slept / Ate / Bottle / Diaper / Medicine / Mood / Other, plus a short text and time | |

After save: sheet closes, the new item animates into the timeline, and an **"Undo"** snackbar shows for 6 seconds
(uses `core.undo`). Batch saves say "Logged for 4 kids · Undo".

**Waking from a nap:** banner avatar tap (1 tap), the "Woke up" button on the open nap card in the timeline, or "Wake
all". Naps over 3h show an amber "still sleeping?" hint on the card (no alarms).

**Photos tagged with several children:** one `photo` entry per child, written to **each child's family Space**
(blobs are encrypted per Space, so each family gets its own copy). Show a warning chip when the selected children span
more than one family: "Visible to 3 families."

### 6.6 Timeline
- **Day-based.** Header shows the date with ‹ › arrows and swipe left/right to change days; tap the date for a calendar
  picker. "Today" jump button when not on today.
- **Filter chips** (horizontal scroll): All · Naps · Food · Diapers · Notes · Photos · Check-in/out · From Home.
- Order: newest first (setting to flip). Times grouped with light hour separators.
- **Visual structure (required):**
  - A continuous **vertical line** runs down the left side from the top of the day's list through the last item
    (2px, muted color).
  - Each item is a **card/box** to the right of the line.
  - A **dot** (12px circle, filled with the kind's color, with a 3px ring in the page background color) sits **on the
    line, vertically centered on the card's header row**, so the line visually passes through each dot.
  - Open naps get a gently pulsing dot (disabled under reduced motion).
- **Card contents:**
  - Header row: kind icon + **type label** · **time** (e.g., "10:42 AM"; naps show "12:30 – 2:05 PM · 1h 35m",
    open naps a live timer) · child name (when showing several kids) · author line ("by Miss Bri", "by Mom 🏡").
  - The **date** comes from the day header, and each card also carries it in an accessible label (and visibly in
    exports).
  - Body: kind-specific summary ("4 oz formula · finished 3.5 oz", "Lunch · Mac & cheese, peas · Ate most", "💧 Wet ·
    cream applied"), the text/caption, photo grid (via `<sync-blob>`; tap to view full-screen with swipe and a
    download/save button).
  - **Reaction bar:** existing reactions as pills with counts (your own highlighted); a "☺+" button opens the 8-emoji
    picker. Long-press a pill to see who reacted.
  - **Thread:** "💬 2 replies" collapses/expands replies under the card (indented, small avatars, timestamps). An
    inline reply box at the bottom of the expanded thread. A new item shows a "Reply" affordance only.
  - Overflow menu (⋯): Edit, Delete (with confirm), "Edit for all in batch" when `batchId` is set, Copy text.
- **Daily summary card** pinned at the top of past days, and available on demand for today (§7.1).
- Empty state: friendly illustration (original artwork, not a known character), "Nothing logged yet today."

### 6.7 Child profile (provider; read-only for parents except Family Notes)
Avatar, names, birth date/age, allergies, care notes, family notes, family members and devices (provider sees revoke
buttons), invite button, archive child.

### 6.8 Settings
- **Everyone:** Theme (System/Light/Dark), Display name, Link another device, This device's sync status, About/version,
  Leave family (parents).
- **Provider:** Daycare & app name, Staff (invite/remove providers), Families (archive), Invite approval toggle,
  Invite expiry, "Since" chip thresholds, Relay URL (default from build config), Exports (§7), Storage usage (blob budget).
- **Sync status pill:** ● Synced / ◐ Syncing (n) / ○ Offline (changes saved on this device). Tapping it opens details:
  transports connected, last sync time, pending packets, blobs downloading.

### 6.9 App update UX
On `app:update-ready`, show a non-blocking banner "Update available · Reload", which calls `host.applyUpdate()`.

## 7. Reports and exports

All generated **on-device** from local data (works offline).

### 7.1 Daily summary (per child, per day)
In-app card + share as image/PDF: arrival/departure times and by whom; total nap time with each nap; bottles (count,
total oz finished); meals/snacks with amounts; diapers (wet/soiled counts); notes; photo thumbnails. Parents and
providers both have it. "Share" uses the Web Share API (fallback: download).

### 7.2 Attendance export (provider)
Date range + family/child filter → **CSV** (`date, child, check_in, checked_in_by, check_out, picked_up_by, hours`) and
a **printable PDF** (print stylesheet + `window.print()`; one page per week, a signature line for the provider). Flag
days with a check-in but no check-out.

### 7.3 Full export / backup
Provider: everything (all families) as a **ZIP** containing `data.json` (all objects, schema version stamped) plus a
`photos/` folder (optional checkbox; photos must be downloaded locally first, so show progress). Parent: same, scoped
to their family. Use a small client-side zip library (e.g., `fflate`).
*Import/restore is out of scope for v1*; data durability comes from sync across devices plus the relay.

## 8. Offline and sync behavior

- Every write is local-first and appears in the UI immediately; live queries (`ctx.data.query(...).subscribe`/
  `LiveElement.bind`) drive all views.
- Transports: WebSocket relay (`wss://…`, URL from build config `RELAY_URL`, overridable in Settings) and WebRTC.
  Add the relay origin to `connectSrc`.
- Photos: `ctx.blobs.attach(file, { space, obj })` works offline; uploads in the background. **Compress before attach:**
  resize to max 2048px on the long edge, JPEG/WebP quality 0.82, strip EXIF (privacy: no GPS) via canvas re-encode.
  Thumbnails load first; full image on tap. Pin today's photos on provider devices; let the blob engine evict older ones
  within the storage budget.
- Conflict behavior: field-level LWW from the framework. Nap end edits from two devices: last writer wins (fine).
  Reactions use deterministic IDs (§5.4). Comments are separate objects.
- Clock skew: display times use `at` (user-chosen), not packet clocks.
- Production builds **must** use `openSecureCore` / `security: 'spaces'`; add a test that `assertSecureCore(core)` passes.

## 9. Non-functional requirements

| Area | Target |
|---|---|
| Performance | Timeline for a day with 150 entries renders < 100ms on a mid-range Android phone; add-flow sheet opens < 100ms. Initial JS (gzip) < 200 KB excluding framework. |
| Installability | Passes `verify-installable`; maskable icon; standalone display; works on iOS Safari 17+ and Android Chrome. |
| Offline | App shell and all data are usable in airplane mode from a cold start after the first load. |
| Security | No plaintext codec in production; no analytics or third-party requests; the CSP stays as generated by `app-build` (plus the relay in `connectSrc`). Render user text with `textContent` / Svelte text bindings only, never `{@html}`. |
| Privacy | EXIF stripped from photos; invite secrets only in URL fragments; invites single-use with 24h default expiry. |
| Data retention | Nothing is hard-deleted by "archive"; "delete" on an entry uses framework delete/undo semantics. |

### 10.2 Svelte and `app-build`
`app-build` bundles with esbuild and has no Svelte plugin. Pick one of these and record it in `DECISIONS.md`:
1. **Preferred:** build `ui/` with Vite in library mode (`ui/dist/ui.js`, an ES module exporting `mount(target, api)`),
   and import that compiled file from the `daycare` module's root view, which passes a thin, typed `api` wrapper over
   `ctx.data`, `ctx.blobs`, and `ctx.spaces`. The Svelte code never touches framework internals.
2. Add an `esbuildPlugins` option to `app-build` (with `esbuild-svelte`) as an upstream PR.

Either way, module code must not import `@sync/core`/`@sync/spaces` (the build enforces this). App-level code
(`app.config.ts`, `authz.ts` registration) may.

### 10.3 Svelte state
Wrap each live query in a Svelte 5 rune-based store (`$state`, subscribe/unsubscribe in `$effect`). One query per
visible day per Space (`where: e => e.fields.at in [dayStart, dayEnd)`), plus comment/reaction queries keyed by
visible entry IDs. Roster aggregates across family Spaces.

### 11.1 Key acceptance tests (E2E, Playwright)
- Provider logs a diaper for a child in **3 taps** from the Roster (long-press card → Diaper → Wet), and it appears
  on the parent's device after sync.
- Batch: select 4 children → Meal → per-child amounts → Save → 4 entries with the same `batchId`; one Undo removes all 4.
- Nap: start for 2 children, banner shows 2 timers, Wake all sets `endAt` on both.
- Parent cannot see another family's children (separate Spaces: data never arrives on their device).
- A parent device's forged `nap` create packet is rejected by provider peers (validator).
- Offline: provider in airplane mode logs 10 entries and a photo; on reconnect, the parent receives them all and the
  photo downloads.
- Invite reuse: a second accept of a single-use invite fails with a clear message.
- Theme: system dark → app dark; override to light persists across reload with no flash.
- Timeline visual: a screenshot test confirms the line, dots, and boxes in light and dark at 375px wide.
